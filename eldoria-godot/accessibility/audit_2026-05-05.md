## Findings (detailed)

### 🔴 1. No text-size setting

**Where:** Main.tscn — every Label has `theme_override_font_sizes/font_size = N` hardcoded (HelpLabel 14, GoldLabel 18, LevelLabel 28, QuestTitle 16, …).

**Problem:** Alden reads at ~6pt at her seat distance from the iMac. Anything below 18pt is fuzzy. The HelpLabel (14) and QuestTitle (16) fall below that.

**Why it matters:** PX rule #1 — kid figures it out without reading text — but when text IS present, it must be *legible*. We've half-failed it today.

**Fix:** add a `Settings` autoload with a `text_scale: float = 1.0` (range 0.85–1.5). UITheme.gd currently has zero references to settings — add a `UITheme.apply_text_scale(node)` and call it on Label init. Or: route every `font_size` through a base constant × scale.

**Filed for:** `qa/_px_flags.md` → @engineering / @ui-agent. PX-only edits to UI.tscn are out of zone.

### 🟠 2. No colorblind palette mode

**Where:** UITheme.gd, Player.gd damage popup colors (red `-N`, gold `CRIT!`, green `+HEAL`).

**Problem:** Red/green damage-vs-heal is the most common deuteranopia trap. Today damage and heal differ ONLY by color (`-` prefix vs `+` prefix helps but the prefix glyph is small at 32pt).

**Why it matters:** ~5% of boys have red/green color vision deficiency. Owen plays with at least 2 friends; one might be deuteranomalous and not know it.

**Fix proposal:**
- Add a `Settings.colorblind_mode: String = "off"` with values `"off" | "deuteranopia" | "protanopia" | "tritanopia"`
- Heal popup keeps green AND adds a `↑` prefix
- Damage popup keeps red AND adds a `▼` prefix
- Boss telegraph rings (red = charge / slam) need an outlined version

**Filed for:** @ui-agent + @combat.

### 🟠 3. No reduce-motion / no-shake toggle

**Where:** Boss.gd telegraphs (lines/rings flash for 0.78s / 0.9s), Player.gd CRIT popup tween, level-up popup, quest-complete toast.

**Problem:** Several systems have rapid color modulation (boss charge red telegraph, slam ring expanding). No shake is implemented today (good — none to disable yet) but when juice arrives it MUST gate on a setting.

**Why it matters:** A small fraction of players (~3%) have motion sensitivity. More relevantly: Alden gets motion-queasy on long sessions. Reducing flashes also helps focus.

**Fix proposal:**
- `Settings.reduce_motion: bool = false`
- All future juice (camera shake, hit-stop, telegraph flashes) reads this on each effect call
- Telegraph flashes → swap to a **steady fill** with no modulation if reduce_motion is on

**Filed for:** @combat + @juice (and PX, since `feel_specs.md` will define which effects gate on this).

### 🟠 4. No hold-to-press / sticky-attack alternative

**Where:** Player.gd attack input requires `Input.is_action_just_pressed("attack")`.

**Problem:** Alden's left-click is jittery in long sessions (small hands, getting tired). A "hold to keep swinging" mode would let her keep pressure on a fight without RSI.

**Fix proposal:**
- `Settings.attack_mode: String = "click"` — `"click"` | `"hold"` | `"toggle"`
- Hold mode: as long as button is down, swing every 0.44s. Same lockout, same arc.
- Toggle mode: click once to start auto-swing, click again to stop.

**Filed for:** @combat / @input.

### 🟡 5. Key remapping not exposed

**Where:** project.godot `[input]` block defines move/jump/attack/interact. No in-game UI to rebind.

**Problem:** Owen plays left-handed. Default WASD doesn't fit his preference (he wants ESDF). Both kids share one keyboard; arrow-key move is bound, so Owen plays arrows + Alden gets WASD. But for E:interact, there's no alternative.

**Fix proposal:**
- Settings page lists all bindable actions with current keys
- Click an action → press a key → rebind (Godot has `InputMap.action_*` API)
- Reset-to-defaults button

**Severity is yellow because** existing dual-binding (WASD + arrows) on movement already absorbs most of the pain. Only `interact`, `attack`, and `jump` lack alternates.

**Filed for:** @ui-agent.

### 🟠 6. Reading load — long NPC dialogue, no read-aloud

**Where:** `data/dialogue/*.json` files, NPC.gd dialogue rendering.

**Problem:** Maeve's lines run 3–4 sentences. Alden reads aloud at ~50 WPM; she'll skip if a panel hits her with 50+ words.

**Fix proposals (any of, ranked):**
1. **Tier-1 dialogue cap**: NPCs' default-line should be ≤ 12 words. Surfaced lore in tier-3+ flags. Owen can find the longer lines by talking again.
2. **TTS pass**: Godot has a `TextToSpeech` plugin via DisplayServer. Add a `Settings.read_aloud: bool` toggle that calls `DisplayServer.tts_speak(line)` when a dialogue panel opens.
3. **Picture-prompts**: complement long text with a small icon row (⚔ / 🏹 / 🛡 / 🌿) showing what the quest is about, so the gist reads in 1 second.

**Filed for:** @dialogue + @ui-agent.

### ✅ Things that ARE good

- **Both WASD and arrows bind to move.** Two kids on one keyboard; left-handed and right-handed both fit.
- **Death is cheap.** 2.5s anim → full-restore respawn at SAFE_SPAWN. PX rule #2 (recoverable in <30s) is far cleaner than the bar requires. Don't regress this.
- **Damage numbers float ABOVE the action.** Outlined, kid-readable. The 32pt for `-N` and 56pt for `CRIT!` are legible from Alden's seat-distance.
- **Toasts are timed deliberately** — World.gd staggers achievement toasts so they don't stomp each other. Good for kids parsing one thing at a time.
- **Auto-aim forgiveness in place.** 118° arc + 2.7m range absorbs most aim error without making the player feel like the game played itself. Keep this; document any future shrink in this audit.

## Suggested settings menu (future)

When `@ui-agent` builds a Settings panel, the bare-minimum set:

1. Text scale — slider 0.85x–1.5x
2. Colorblind mode — Off / Deuteranopia / Protanopia / Tritanopia
3. Reduce motion — toggle (gates camera shake, telegraph flashes, screen-fade severity)
4. Attack input — Click / Hold / Toggle
5. Read dialogue aloud — toggle (TTS)
6. Key bindings — full remapper
7. Damage numbers — On / Smaller / Off
8. Sound — master / SFX / music / ambient (4 sliders)
9. Reset save (with confirm)
