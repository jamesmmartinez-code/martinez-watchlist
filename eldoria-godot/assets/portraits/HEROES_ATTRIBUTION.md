| File                       | Hero / class            | Silhouette band                                | Palette anchor                                |

| `alden_pathfinder.png`     | Alden, Pathfinder (bow) | hooded ranger + diagonal longbow + arrow shaft | forest moss + amber + mint highlight + brass  |

Each portrait is a hand-painted-feel bust on a painterly gradient
background with the same soft rounded-rect alpha mask + speckle frame
used by `gen_enemy_portraits.py` and `gen_bandit_captain_portrait.py`,
so all character portraits read in one family at codex thumbnail size.

## Why these exist

`CharacterSelect.gd` shipped a giant emoji avatar ("★" Alden, "✦" Owen)
in `_make_hero_card` with the comment "placeholder until hero portrait
images ship". The two playable heroes are the FIRST thing every player
sees on boot — a painterly bust per hero will read as a real fantasy
adventurer rather than a star glyph, in the same painterly family as
the NPC + enemy portraits the codex already uses.

## Wiring (Character Select — done in this same run)

`CharacterSelect.gd._make_hero_card` now:
  1. Maps the hero `id` ("alden" / "owen") to a portrait slug
     ("alden_pathfinder" / "owen_vanguard") that mirrors the
     `Player.gd` hero_paths basenames (zero new id space).
  2. `ResourceLoader.exists()`-checks the PNG path before loading.
  3. If the texture loads, places a `TextureRect`
     (`STRETCH_KEEP_ASPECT_CENTERED`, custom_minimum_size 0,320)
     where the emoji label used to live.
  4. Otherwise, falls back to the original giant emoji `Label` block
     unchanged. This is the same fail-soft pattern Items.gd uses for
     `icon_path` over `icon`, and Achievements.gd uses for
     `icon_path` over `icon`.

So a partial checkout (or a future hero added before its portrait
ships) will continue to show a recognisable star/sigil on the
Character Select screen instead of an empty card.

## Style compliance — THEME.md

- §1 painterly hand-painted concept-art aesthetic — `_draw_painter_blob`
  soft-edge ellipse stamping along polygon outlines, Gaussian blur
  before LANCZOS downsample to break crisp vector edges.
- §3 palette — sunset gold, burnt orange, moss green, parchment, ink,
  crimson, brass. The two hero accents (mint #8CF0A5 ≈ COL_ALDEN, and
  McLaren orange #FF8000 ≡ COL_OWEN) are pulled from the hero card
  border colours so the portrait and frame read as one unit.
- §4 silhouette-distinct — Alden=hooded ranger w/ bow over shoulder,
  Owen=helmed swordsman w/ shield. The two are also silhouette-distinct
  from every existing NPC + enemy portrait (no other portrait has a
  diagonal longbow + arrow, or a round shield held at chest).
- §5 hand-painted, not crisp vector — same painterly speckle frame +
  soft rounded-rect alpha mask + 0.30·SUPER Gaussian blur as the
  enemy portraits.
- §7 child-safe — friendly faces, open eyes, freckles (Alden), determined
  but not grim (Owen). No scars on the heroes (the scar is reserved for
  the bandit_captain mini-boss, where it's a silhouette differentiator).
- §10 Hard Rule 9 — older / weathered / hand-made: leather creases on
  Alden's jerkin, helm scuffs on Owen's brass rim, rivets, frayed cloak
  speckle, hand-cut wood-grain on the shield planks.

## How a future Builder/UI run could extend these

  1. Hero card hover/highlight effect could swap to a "ready stance"
     variant of the same bust (different seed, slight pose tweak).
     The HEROES dict in `gen_hero_portraits.py` is keyed on slug — add
     `alden_pathfinder_ready.png` / `owen_vanguard_ready.png` entries
     with a small pose delta and CharacterSelect wires them in via
     mouse_entered / mouse_exited.
  2. In-game dialogue panel could show the hero portrait when the
     player speaks (currently shows NPC portrait only). The same
     `res://assets/portraits/<hero_slug>.png` path resolves; one
     conditional in DialoguePanel wires it.
  3. Achievement-toast / level-up VFX could reuse the hero portrait
     as the "you" face — same path, same fail-soft pattern.
