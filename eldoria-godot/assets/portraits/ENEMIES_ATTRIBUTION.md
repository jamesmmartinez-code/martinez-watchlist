# Eldoria Enemy Bestiary Portraits — Attribution

The 8 enemy portrait files in this directory are procedurally generated by
`scripts/art/gen_enemy_portraits.py` (committed alongside).
No third-party images, fonts, or trademarks are used.

## Why these exist

THEME.md S4 lists Goblins, Goblin Brutes, Goblin Warlord, Wolves (Dire),
Skeletons (planned), Crystal Elementals (planned), and Bandits (planned)
as the canonical enemy roster. The 7 NPC portraits in this folder
(maeve, smith_edda, mara, lyra, bram, roan, hala plus 6 satellite-town
NPCs) gave dialogue panels a painted face to show, but the bestiary side
had no painterly face for:

  - the codex / "monster manual" panel a Builder/UI run can wire next
  - boss-intro splash for goblin_warlord and crystal_guardian
  - loot-toast headers (`hp_potion_s` looks like it dropped from a
    real-feeling adversary, not a procedural hostile cube)
  - the future dialogue lines bandits and skeletons will speak

These 8 portraits fill that gap without bringing in any third-party
artwork, keeping the existing CC0 + procedural-Pillow pipeline pattern:

```
emoji glyph (legacy)  ->  painterly PNG (icon_path / portrait file)
```

The pattern was first used by `gen_achievement_icons.py` (5 crests),
extended by `gen_affix_icons.py` (6 affix overlay badges), and now
extends to enemy bestiary portraits.

## Style targets (THEME.md compliance)

  - S1 painterly hand-painted concept-art aesthetic - soft brushstroke
    edges from `_draw_painter_blob` stamping soft-edge ellipses along
    every silhouette edge, plus 0.3*SUPER Gaussian blur + LANCZOS
    downsample at finalise.
  - S3 palette compliance - every accent colour resolves to a hex in
    THEME.md S3 primary / secondary / magic bands. No neon, no
    fluorescent, no pure white. Magic accents (fey-cyan FOR crystals
    and skeleton flames; arcane purple ONLY on crystal_guardian) used
    sparingly, never on the human/goblin/wolf base portraits.
  - S4 silhouette-distinct - small hunched (grunt), helmed (brute),
    crowned-and-bannered (warlord), long-snouted (wolf), round-skull
    (skeleton), jagged-shard (elemental), tall-arcane (guardian),
    hooded-cloaked (bandit) - eight readable thumbnails at codex size.
  - S5 hand-painted look, not crisp vector. Painterly speckle frame
    around the rounded-rect edge replaces a crisp UI border.
  - S7 child-safe - no detailed gore, no torture imagery. Wolf has
    glowing eyes + a cheek scar; skeleton has a stylised skull (no
    decay imagery); warlord has 3 minor face scratches. All within
    the THEME S7 child-safe bound.
  - S10 Hard Rule 9 - when in doubt, choose the older / weathered /
    hand-made option. Each portrait carries painterly speckle and
    edge-stippling, not a flat-UI silhouette.

## How a future Builder/UI run can wire these

A new optional field can be added to `Enemy.gd` (or a parallel
`Bestiary.gd`):

```gdscript
const ENEMY_PORTRAITS = {
    "goblin":            "res://assets/portraits/goblin_grunt.png",
    "goblin_brute":      "res://assets/portraits/goblin_brute.png",
    "goblin_warlord":    "res://assets/portraits/goblin_warlord.png",
    "wolf":              "res://assets/portraits/dire_wolf.png",
    "skeleton":          "res://assets/portraits/skeleton_warrior.png",
    "crystal_elemental": "res://assets/portraits/crystal_elemental.png",
    "crystal_guardian":  "res://assets/portraits/crystal_guardian.png",
    "bandit":            "res://assets/portraits/bandit_hooded.png",
}
```

Then any boss-intro splash, codex panel, or loot-toast can show the
matching face without any further art work. Mirrors how
`Items.icon_path` and `Achievements.icon_path` were wired by prior
Builder/Polisher runs.
