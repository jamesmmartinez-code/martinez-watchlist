  prevents any boxy disc edge.

## Why these exist

`Items.AFFIX_SUFFIXES` previously carried only an emoji `icon_overlay`
field (❄ 🔥 🐻 💨 🐉 ✨). Emoji rendering is a flat-UI / modern artefact
that fights THEME §1 (✗ Anime/manga, ✗ flat-UI styles in §5). These PNGs
provide a painterly replacement for the bag-grid overlay so the player
silhouette of an "Sharpened Steel Blade of the Bear" reads as bear-claw
heraldry rather than a phone keyboard glyph.

A new additive field `affix_icon_path` was added to each
`AFFIX_SUFFIXES` entry pointing at the matching PNG. The original
`icon_overlay` emoji string was preserved untouched — no UI consumer is
broken by this change. A future Builder/Polisher run can swap the bag UI
to prefer `affix_icon_path` over `icon_overlay` when present, exactly as
prior runs wired `Items.icon_path` for the base 24 item icons.

### Why these exist

`Items.AFFIX_PREFIXES` previously had no visual indicator at all — the
suffix table had `icon_overlay` (emoji) AND `affix_icon_path` (PNG)
fields, but the prefix table had only stat modifiers. That made affix
prefixes invisible in any future bag-grid / tooltip rendering. These 7
crests close the parity gap: every affix entry — prefix OR suffix — now
carries an `affix_icon_path` pointing at a painterly 64×64 PNG.

A matching `tint` field was also added to each prefix entry, mirroring
the suffix schema. The tint is the rarity-band colour the UI can use to
modulate the slot frame OR the icon glow for that rarity tier:
- uncommon → green tints
- rare → blue tints (warm-brass for Heroic, cool-stone for Fierce)
- epic → arcane purple
- legendary → sunset gold

A future Builder/Polisher run can render the prefix crest in the
inventory slot's top-left corner (mirror the bag-grid suffix overlay
location) and modulate the slot frame with the tint, exactly the same
treatment the suffix overlays will get when the
`prefer affix_icon_path over icon_overlay` UI patch lands. Until then
the new fields are additive metadata only — no existing UI consumer is
affected.
