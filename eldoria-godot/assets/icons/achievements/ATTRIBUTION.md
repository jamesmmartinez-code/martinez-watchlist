Each crest is a hand-painted-feel disc with a stylised heraldic symbol on a
slightly weathered painterly rim. Style targets THEME.md:

- §1 painterly, hand-painted concept-art aesthetic — soft brushstroke rim,
  Gaussian-softened edges (no crisp vector look).
- §3 palette compliance — every accent colour resolves to a hex in
  THEME.md §3 primary / secondary / magic bands. No neon, no
  fluorescent, no pure white background (transparent alpha used instead).
- §5 "Hand-painted look, not crisp vector" — final 0.30·SUPER Gaussian
  blur + LANCZOS downsample blends edges; soft circular alpha mask
  prevents any boxy disc edge.
- §10 Hard Rule 9 — when in doubt, choose the older / weathered /
  hand-made option (heraldic crest > flat sticker).

## Why these exist

`Achievements.ACHIEVEMENTS` previously carried only an emoji `icon`
field (🌱 🐺 ⚔ 🤝 🏰 🔨 🐺-pact). Emoji rendering is a flat-UI / modern artefact
that fights THEME §1 (✗ Anime/manga, ✗ flat-UI styles in §5). These PNGs
provide a painterly replacement for any future achievement panel,
unlock toast, or title chooser so the player's milestone reads as a
medieval crest rather than a phone keyboard glyph.

A new additive field `icon_path` was added to each `ACHIEVEMENTS`
entry pointing at the matching PNG. The original `icon` emoji string
was preserved untouched — no UI consumer is broken by this change. A
future Builder/Polisher run can swap the unlock toast / achievement
panel UI to prefer `icon_path` over `icon` when present, exactly as
prior runs wired:

- `Items.icon_path` for the base 24 item icons (existing PNG icons).
- `Items.AFFIX_SUFFIXES.affix_icon_path` for the 6 affix overlay badges
  (existing painterly affix overlays).

This is the third tier of the same pipeline:

```
emoji glyph (legacy)  →  painterly PNG (icon_path)
```
